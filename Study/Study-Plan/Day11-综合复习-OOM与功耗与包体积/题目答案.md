## 口述题

#### 1. OOM 有哪些类型？分别是什么原因导致的？如何监控？（口述题）
**要点：**
- Java Heap OOM：对象泄漏/大对象，监控 `Runtime.maxMemory`、`dumpsys meminfo`、LeakCanary。
- Native Heap OOM：Bitmap/native 分配，监控 `malloc`/`ndk-stack`。
- GPU/Graphic OOM：纹理太大，监控 `adb shell dumpsys gfxinfo`。
- 线程/栈 OOM：线程数过多或递归深度，监控 `top`、`/proc/<pid>/task`。
- 资源句柄泄漏（FD OOM）：文件/Socket 未关闭，监控 `lsof`。

**解析：**
可通过内存监控 SDK 上报 PSS、Heap、native size。使用 `Android Studio Profiler`、`MAT`、`perfetto` 分析热点；FD 泄漏可用 `StrictMode` 或 `CloseGuard`。不同类型的解决方案不同：Java Heap 关注对象生命周期，Native Heap 注意 Bitmap/so 分配，GPU OOM 需优化分辨率、压缩纹理。

#### 2. 热修复的类加载方案（如 Tinker）和 native 方案（如 Sophix）的原理区别（口述题）
**要点：**
- 类加载方案：插入补丁 Dex，在 ClassLoader 搜索链前置，替换方法实现。
- Native 方案：直接修改内存中方法指针/ELF Symbol（如 AndFix, Sophix），无需重启。
- 类加载方案兼容性好但需重启；native 方案即时生效但风险更高。

**解析：**
Tinker 等方案通过将补丁 Dex 插到 `DexPathList` 前面，重启后新类优先生效，并可合成基线 APK。Native 方案通过 Hook `art::ArtMethod` 或 inline Hook 修改指针，立即替换，但受 Android 版本/指令集限制，需处理校验和安全风险。

#### 3. 你的 App 包体积从 80MB 优化到 50MB，你做了哪些事情？（口述题）
**要点：**
- 启用 R8/Proguard，移除无用类与资源，配置 `keep` 精准。
- 资源优化：WebP/AVIF、移除重复资源、使用 `resConfig`、动态下发 So。
- ABI 拆分：`abiFilters` + `bundle` 动态交付。
- 三方库瘦身：按需引入、拆分模块、使用 `implementation` 避免传递依赖。

**解析：**
还可利用 App Bundle 的 `split` 功能仅交付所需语言/屏幕密度；SO 动态下发或使用 `ReLinker` 加载网络下载的 so；把大体积数据迁移到远程（如内置模型/字体改为按需下载）。

## 场景分析题

#### 4. 线上大量用户出现 OOM，但 Java Heap 使用量并不高，可能是什么原因？（场景分析题）
**要点：**
- 可能是 native 内存泄漏（Bitmap、ByteBuffer、音视频组件）。
- WebView、OpenGL、三方 SDK 使用的 native 资源；或文件描述符耗尽。
- 应该采集 PSS、native heap，通过 `dumpsys` 检查 `Native Heap`、`Graphics`、`GL` 段。

**解析：**
Android 的 `dumpsys meminfo` 中 `Native Heap`、`Graphics`、`GL` 可指示 native 使用量。也可用 `heapprofd`、`perfetto` 抓取 native heap profile。针对 Bitmap 泄漏，可强制启用 `BitmapFactory.Options.inBitmap`、使用 `ImageDecoder` 控制尺寸。音视频 SDK 需调用 `release()`。

#### 5. 产品要求 App 能在后台精准推送消息，但 Android 8.0+ 后台限制越来越严，如何实现？（场景分析题）
**要点：**
- 使用 FCM/厂商 Push，尽量依托系统级推送通道，避免自己常驻前台服务。
- 后台任务使用 `WorkManager` + `setExpedited`/`setForeground`，并结合通知渠道。
- 重要消息可使用高优先级 FCM + `pendingIntent` 打开前台 Activity。

**解析：**
Android 8.0 引入后台执行限制，普通后台服务在几分钟后被强制停止。解决方案是：依赖系统推送通道（如 FCM），必要时使用前台服务（显示通知）。若需要拉活，可配合 `JobScheduler`/`AlarmManager#setExactAndAllowWhileIdle`，但要遵守 Doze 频率。对国产 ROM，可以使用厂商推送 SDK 与账号白名单。
