## 口述题

#### 1. 从 MVC 到 MVI，每次演进解决了什么问题？引入了什么新问题？（口述题）
**要点：**
- MVC：Controller 与 View 紧耦合，适合小项目但难以测试。
- MVP：Presenter 解耦 View 与 Model，但 Presenter 过于臃肿、生命周期协调复杂。
- MVVM：数据驱动 UI，降低模板代码，但 LiveData/双向绑定可能导致状态不可控。
- MVI：单向数据流、不可变 State，便于时间旅行调试，但心智负担更高，需要标准化意图处理。

**解析：**
演进核心是“可维护性 + 状态管理”。MVP 解决了 MVC 中 View 直接操作 Model 的问题，但 Presenter 容易变成上帝类。MVVM 借助 ViewModel + LiveData/Flow，UI 观察状态变化自动更新；然而状态来源分散时仍易出现竞态。MVI 引入单入口 intents、reducer，所有状态都通过不可变对象推进，方便记录与回放，但初学者需适应 reducer/intent 模式。

#### 2. ViewModel 为什么能在屏幕旋转后保留数据？从源码角度解释（口述题）
**要点：**
- Activity 销毁重建时，`ComponentActivity` 把 ViewModelStore 保存在 `NonConfigurationInstances`。
- 新 Activity 会复用 `ViewModelStore`, 同名 ViewModel 不会被销毁。
- 只有 `onCleared()` 在 `finish` 或进程被杀时调用。

**解析：**
`ComponentActivity#retainNonConfigurationInstances()` 将 ViewModelStore 包裹到 `LastNonConfigurationInstances` 并交给 AMS，重建时再取回。ViewModelProvider 以 `ViewModelStore`+`Factory` 为 key，因此只要同一 scope（Activity/Fragment）还在，ViewModel 就能跨配置变更存活。

#### 3. LiveData 的粘性事件是什么？为什么会有这个问题？怎么解决？（口述题）
**要点：**
- 粘性事件：新观察者会立即收到 LiveData 最后一次 `setValue`（即便数据过期）。
- 原因：LiveData 内部持有 `mDataVersion` 和 `mVersion`，新订阅时若版本落后会立刻分发一次。
- 解决：使用 `Event` 包装类、`SingleLiveEvent`、或迁移到 SharedFlow。

**解析：**
LiveData 设计用于存储状态，自然希望新观察者立即获得当前状态。但对于一次性事件（导航、Toast）会重复触发。常见方案是 `Event<T>`（只消费一次）、或干脆使用 SharedFlow/Channel，并在 Flow 中控制重放。

## 场景分析题

#### 4. 你的团队要从 MVP 迁移到 MVVM，迁移策略是什么？有哪些坑？（场景分析题）
**要点：**
- 从 Presenter 中抽取业务逻辑到 UseCase/Repository，ViewModel 只做状态组合。
- 先迁移低风险页面，并保持接口层不动。
- 坑点：生命周期/协程作用域选择、数据多源同步、旧界面仍需要接口回调。

**解析：**
建议分层：Domain（UseCase）、Data（Repository）、Presentation（ViewModel+UI）。迁移步骤：1) 为旧界面添加 ViewModel，逐步将 Presenter 内的状态迁移；2) 通过 LiveData/StateFlow 把 UI 状态串起来；3) 最终删除 Presenter。注意在协程中使用 `viewModelScope`，确保不会泄漏 Activity。

#### 5. 一个大型 App（50+ 模块），你如何设计组件化架构？模块间如何通信？（场景分析题）
**要点：**
- 按业务域拆分 feature module + base module，公共能力抽到 core/lib 层。
- 路由通信使用 ARouter/自定义服务接口，避免显式依赖。
- 数据通信可通过接口下沉到 `service` 模块或使用事件总线/Repository。

**解析：**
组件化要解决：构建时间、隔离性、协作效率。推荐结构：`app`(壳) + `feature-*` + `lib-*` + `service-*`。模块间通过路由（ARouter, Navigator）跳转和通过接口/Service Locator 获取依赖。可结合 Hilt 提供依赖注入，Gradle 中使用 `buildSrc` + `Version Catalog` 管理依赖。

## 代码题

#### 6. 实现一个简单的 MVI 架构示例（ViewModel + StateFlow + sealed class Intent/State）（代码题）
**要点：**
- 定义 `Intent`（用户意图）、`State`（UI 状态）、`Result`（可选中间态）。
- ViewModel 收集 Intent，使用 reducer 推导新状态，通过 `StateFlow` 暴露给 UI。
- UI 通过 `collectLatest` 订阅状态，并在 `sendIntent()` 时发射意图。

**解析：**
示例演示计数器：`Increment`/`Decrement`/`Load` 等意图，状态包含当前计数与加载状态。

**示例代码：**
```kotlin
sealed interface CounterIntent {
    data object Increment : CounterIntent
    data object Decrement : CounterIntent
    data object LoadInitial : CounterIntent
}

data class CounterState(
    val value: Int = 0,
    val loading: Boolean = false,
    val error: String? = null
)

class CounterViewModel : ViewModel() {
    private val _state = MutableStateFlow(CounterState())
    val state: StateFlow<CounterState> = _state

    private val intents = Channel<CounterIntent>(Channel.UNLIMITED)

    init {
        viewModelScope.launch {
            intents.receiveAsFlow().collect { intent ->
                when (intent) {
                    CounterIntent.LoadInitial -> loadInitial()
                    CounterIntent.Increment -> reduce(_state.value.value + 1)
                    CounterIntent.Decrement -> reduce(_state.value.value - 1)
                }
            }
        }
    }

    fun sendIntent(intent: CounterIntent) {
        intents.trySend(intent)
    }

    private suspend fun loadInitial() {
        _state.update { it.copy(loading = true, error = null) }
        delay(200)
        _state.update { it.copy(loading = false, value = 42) }
    }

    private fun reduce(newValue: Int) {
        _state.update { it.copy(value = newValue.coerceAtLeast(0)) }
    }
}

// UI 层示例
@Composable
fun CounterScreen(viewModel: CounterViewModel = viewModel()) {
    val state by viewModel.state.collectAsState()
    LaunchedEffect(Unit) { viewModel.sendIntent(CounterIntent.LoadInitial) }
    Column {
        Text(text = "Count: ${state.value}")
        Row {
            Button(onClick = { viewModel.sendIntent(CounterIntent.Decrement) }) { Text("-") }
            Button(onClick = { viewModel.sendIntent(CounterIntent.Increment) }) { Text("+") }
        }
        if (state.loading) CircularProgressIndicator()
    }
}
```

**说明：**
ViewModel 作为单一状态源，UI 订阅 `StateFlow`。`Channel` 保证 Intent 顺序处理，如需 Thread-safe，可用 `MutableSharedFlow`。Composable 仅渲染状态，减少副作用。
