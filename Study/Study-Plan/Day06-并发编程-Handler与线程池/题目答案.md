## 口述题

#### 1. 画出 Handler 消息机制的完整流程图（子线程发消息 → 主线程处理）（口述题）
**要点：**
- 子线程通过 `Handler.sendMessage` 将消息加入主线程 `MessageQueue`。
- `Looper.loop()` 轮询 `queue.next()`，取到 Message 交给对应 Handler 的 `dispatchMessage`。
- Handler 最终回调 `handleMessage` 或 `Runnable`，执行后通过 `message.recycleUnchecked` 复用。

**解析：**
`MessageQueue.enqueueMessage` 会按照 `when` 排序，`nativeWake` 唤醒阻塞中的 Looper。主线程 Looper 在 `loop()` 中阻塞，`MessageQueue.next()` 会调用 native 层 `nativePollOnce`，处理同步屏障/IdleHandler。当消息被处理后，如果 `Message.target` 为 Handler 则进入 `dispatchMessage`。了解流程有助于分析消息延迟、IdleHandler、同步屏障等机制。

#### 2. ThreadPoolExecutor 的任务执行流程（核心线程→队列→非核心线程→拒绝策略）（口述题）
**要点：**
- 提交任务时优先创建核心线程（少于 corePoolSize）。
- 核心线程满后放入阻塞队列；队列满后尝试创建非核心线程（<= maximumPoolSize）。
- 若仍无法执行则触发 `RejectedExecutionHandler`。

**解析：**
ThreadPoolExecutor 的构造函数包含 7 个参数（核心/最大线程数、存活时间、时间单位、阻塞队列、ThreadFactory、拒绝策略）。任务执行顺序由 `execute()` 中的 CAS（`ctl`）控制：先尝试新增核心线程，失败则入队；若队列满则尝试 `addWorker(command, false)` 新建非核心线程。默认拒绝策略为 `AbortPolicy` 抛异常，可根据场景选择 CallerRuns、Discard 等。理解流程可指导线程池调优。

#### 3. 什么是同步屏障？为什么 VSYNC 渲染需要用同步屏障？（口述题）
**要点：**
- 同步屏障是插入 MessageQueue 的特殊条目，只允许异步消息（如 Choreographer）通过。
- 插入屏障后，普通同步消息会被阻塞直至屏障移除。
- 渲染场景通过屏障确保动画/vsync 回调优先于普通任务，以避免掉帧。

**解析：**
`MessageQueue` 有 `mQuitting`、`mMessages` 和 `mBlocked` 状态，通过 `postSyncBarrier` 插入 `Message`（`target=null`），阻止同步消息。`Choreographer` 在每帧开始前插入屏障，确保渲染任务可在主线程繁忙时仍获得执行机会。渲染完成后通过 `removeSyncBarrier` 移除，恢复普通消息消费。

## 场景分析题

#### 4. 主线程的 Looper.loop() 是一个死循环，为什么不会 ANR？（场景分析题）
**要点：**
- loop() 虽然 while(true)，但 `MessageQueue.next()` 在队列空时会阻塞在 epoll/wake 机制，不会占用 CPU。
- ANR 的真正原因是主线程长时间执行耗时任务或被同步锁阻塞，而非 loop() 结构。
- ANR 监控来自系统 Watchdog（5s/10s），只要消息能在超时时间内处理完就不会触发。

**解析：**
Looper 的死循环是事件驱动模型的体现，阻塞在 native poll 中等待 epoll 唤醒。当主线程处理的消息/输入事件超过 5s（前台）或 BroadcastReceiver 超过 10s，就会被 AMS 判定为 ANR。因此关键在于避免在主线程执行耗时 I/O/计算，必要时 offload 至线程池或协程。

#### 5. OkHttp 的线程池为什么用 0 核心线程数？这样设计的好处是什么？（场景分析题）
**要点：**
- OkHttp 的 `TaskRunner` 使用 `ThreadPoolExecutor(0, Integer.MAX_VALUE, 60s, SynchronousQueue)`。
- 0 核心线程 + SynchronousQueue 像是缓存线程池，任务完成 60s 后线程自动回收。
- 优点：并发请求多时可快速扩容，空闲时不占资源。

**解析：**
网络请求属于突发型并发，提前保持大量核心线程会浪费内存。SynchronousQueue 不存储任务，提交时若无空闲线程会创建新线程；请求结束 60s 后线程退出。配合连接池，OkHttp 能在高并发场景下依然保持较小开销。

## 代码题

#### 6. 用 CountDownLatch 实现"3 个接口并行请求，全部完成后合并结果刷新 UI"（代码题）
**要点：**
- 创建 `CountDownLatch(3)`，每个请求完成后 `countDown()`。
- 在后台线程等待 latch 归零，再切回主线程合并结果。
- 注意异常处理和超时保护。

**解析：**
示例使用固定线程池并模拟网络延迟，真实场景下可结合 Retrofit + 协程。`await(long timeout, TimeUnit unit)` 可避免无限挂起。

**示例代码：**
```java
import java.util.concurrent.*;

public class ParallelRequests {
    private final ExecutorService pool = Executors.newFixedThreadPool(3);

    public void fetchAll() {
        CountDownLatch latch = new CountDownLatch(3);
        StringBuilder result = new StringBuilder();

        Runnable api1 = () -> {
            try {
                TimeUnit.MILLISECONDS.sleep(200);
                result.append("UserInfo ");
            } catch (InterruptedException ignored) {
            } finally {
                latch.countDown();
            }
        };

        Runnable api2 = () -> {
            try {
                TimeUnit.MILLISECONDS.sleep(150);
                result.append("Orders ");
            } catch (InterruptedException ignored) {
            } finally {
                latch.countDown();
            }
        };

        Runnable api3 = () -> {
            try {
                TimeUnit.MILLISECONDS.sleep(100);
                result.append("Coupons ");
            } catch (InterruptedException ignored) {
            } finally {
                latch.countDown();
            }
        };

        pool.submit(api1);
        pool.submit(api2);
        pool.submit(api3);

        new Thread(() -> {
            try {
                if (latch.await(1, TimeUnit.SECONDS)) {
                    postToMain(result.toString());
                } else {
                    postToMain("timeout");
                }
            } catch (InterruptedException ignored) {
            }
        }).start();
    }

    private void postToMain(String text) {
        // 在 Android 中可使用 Handler(Looper.getMainLooper()) 或 runOnUiThread
        System.out.println("Merged result: " + text);
    }

    public static void main(String[] args) {
        new ParallelRequests().fetchAll();
    }
}
```

**说明：**
示例中将合并逻辑放在单独线程等待 latch，更贴合 Android 可用协程 `async/awaitAll`。记得在页面销毁时取消任务或关闭线程池。
