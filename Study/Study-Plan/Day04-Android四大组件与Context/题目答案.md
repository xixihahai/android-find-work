## 口述题

#### 1. Activity A 启动 Activity B，两者的生命周期调用顺序？如果 B 是透明 Activity 呢？（口述题）
**要点：**
- 普通场景：A `onPause` → B `onCreate/onStart/onResume` → A `onStop`。
- B 为透明/对话框主题时，A 只执行 `onPause` 不进入 `onStop`，因为仍部分可见。
- 返回时逆序调用：B `onPause/onStop/onDestroy` → A `onRestart/onStart/onResume`。

**解析：**
`ActivityThread` 在处理 `LAUNCH_ACTIVITY` 时先给旧 Activity 发送 `onPause`，确保新 Activity 不会抢占资源。若新 Activity theme 透明，WindowManager 不会把 A 的窗口 Z-Order 完全遮挡，A 处于 paused 但仍 visible，因而不会回调 `onStop`。了解顺序有助于决定资源释放时机，例如在 `onStop` 中释放摄像头避免来回切换卡顿。

#### 2. 为什么不能用 Application Context 显示 Dialog？从 Window Token 机制解释（口述题）
**要点：**
- Dialog 需要依附拥有 `Window` 的 `Activity`，并通过 `WindowManager.addView()` 传入有效 `windowToken`。
- Application Context 没有窗口 token，WindowManager 会抛出 `BadTokenException`。
- 只有系统级类型（TYPE_APPLICATION_OVERLAY）配合权限才能脱离 Activity。

**解析：**
`WindowManagerGlobal.addView(View, LayoutParams, Display, ParentView)` 会校验 `token`。`Activity` 创建 `PhoneWindow` 时将 `token` 设置为 `ActivityRecord.appToken`。Application Context 不隶属某个任务栈，无法提供 token，自然无法添加窗口。此外，使用 Activity Context 还可以跟随生命周期在 `onDestroy` 自动 dismiss，避免 Window 泄漏。

#### 3. Binder 为什么比 Socket 快？一次拷贝和两次拷贝的区别（口述题）
**要点：**
- Binder 基于 mmap 共享内存，数据仅需一次用户态→内核态的拷贝。
- Socket/管道通常需要用户态→内核态→用户态两次拷贝。
- Binder 驱动还带有线程池调度和引用计数，减少上下文切换。

**解析：**
Binder 驱动在发送端将数据写入 Binder Buffer（位于内核空间映射的内存），接收端直接映射同一块内存读取，避免再次拷贝到接收方用户态。传统的 Socket 需要 send 将数据从用户态复制到内核缓冲，再由内核复制到接收方用户缓冲。少了一次拷贝意味着更低的 CPU/Cache 开销。Binder 还为每个进程维护线程池和事务栈，提高了跨进程调用效率。

## 场景分析题

#### 4. 微信从聊天页跳转到朋友圈再返回，任务栈是怎么变化的？如果聊天页是 singleTask 呢？（场景分析题）
**要点：**
- 默认情况下，聊天页与朋友圈在同一任务栈，跳转时朋友圈压栈在顶部。
- 返回键弹出栈顶恢复聊天页。
- 若聊天页声明 `singleTask` 且启动新的 `taskAffinity`，可能会复用已有实例并清空其上的 Activity。

**解析：**
普通 `standard` 启动模式：`ActivityA`(聊天)→`ActivityB`(朋友圈)。B 启动后任务栈为 [Launcher, …, A, B]。按返回键 B destroy，A `onRestart/onStart/onResume`。若 A 定义 `singleTask` 并指定不同 `taskAffinity`，则启动 A 会检查目标任务栈是否已存在实例，若有则调用其 `onNewIntent` 并 `FLAG_ACTIVITY_CLEAR_TOP` 清理上方 Activity，在复杂场景可避免重复创建聊天页。

#### 5. 你的 App 有推送进程（:push），当推送到来时如何跳转到主进程的某个页面？（场景分析题）
**要点：**
- 推送进程接到消息后通过显式 Intent + `FLAG_ACTIVITY_NEW_TASK` 启动壳 Activity。
- 可使用 `BroadcastReceiver` 或 `PendingIntent` 通知主进程，再根据路由跳转。
- 需要保证多进程共享数据（使用 ContentProvider、MMKV 多进程或 AIDL）。

**解析：**
由于 :push 与主进程不同，直接启动 Activity 需要 `NEW_TASK` 标志。通常流程为：消息到达 → push 进程逻辑解析 → 构造显式 Intent（含路由参数）→ `context.startActivity(intent.addFlags(Intent.FLAG_ACTIVITY_NEW_TASK))`。若希望先唤起主进程再跳页，可发送本地广播（`LocalBroadcast` 仅限同进程，需改为 `Context.sendBroadcast`）或使用 `JobIntentService` 分发。数据共享可通过 Room 多进程模式或 ContentProvider，避免直接访问内存对象的同步问题。

## 代码题

#### 6. 实现一个跨进程的 Messenger 通信示例（Service 端 + Client 端）（代码题）
**要点：**
- Service 端创建 `Handler` + `Messenger`，在 `onBind` 返回 Binder。
- Client 端通过 `ServiceConnection` 获取 `Messenger` 并发送 `Message`，通过 `replyTo` 回传结果。
- 需要在 `AndroidManifest` 声明 Service 运行在 `:remote` 进程。

**解析：**
Messenger 基于 Binder 封装，适合轻量级 IPC。Service 端 Handler 运行在主线程，可在收到消息时处理业务并通过 `replyTo` 发送响应。示例展示最小可运行代码。

**示例代码：**
```java
// RemoteService.java （AndroidManifest 中声明 android:process=":remote"）
public class RemoteService extends Service {
    static final int MSG_HELLO = 1;

    private final Handler handler = new Handler(Looper.getMainLooper()) {
        @Override
        public void handleMessage(Message msg) {
            if (msg.what == MSG_HELLO) {
                Bundle data = msg.getData();
                String text = data.getString("payload");
                Message reply = Message.obtain(null, MSG_HELLO);
                Bundle bundle = new Bundle();
                bundle.putString("reply", "Server received: " + text);
                reply.setData(bundle);
                try {
                    msg.replyTo.send(reply);
                } catch (RemoteException e) {
                    e.printStackTrace();
                }
            } else {
                super.handleMessage(msg);
            }
        }
    };

    private final Messenger messenger = new Messenger(handler);

    @Override
    public IBinder onBind(Intent intent) {
        return messenger.getBinder();
    }
}

// ClientActivity.java
public class ClientActivity extends AppCompatActivity {
    private Messenger serviceMessenger;
    private final Messenger clientMessenger = new Messenger(new Handler(msg -> {
        if (msg.what == RemoteService.MSG_HELLO) {
            String reply = msg.getData().getString("reply");
            Log.d("Client", reply);
            return true;
        }
        return false;
    }));

    private final ServiceConnection connection = new ServiceConnection() {
        @Override
        public void onServiceConnected(ComponentName name, IBinder service) {
            serviceMessenger = new Messenger(service);
            sendHello();
        }

        @Override
        public void onServiceDisconnected(ComponentName name) {
            serviceMessenger = null;
        }
    };

    private void sendHello() {
        try {
            Message msg = Message.obtain(null, RemoteService.MSG_HELLO);
            Bundle bundle = new Bundle();
            bundle.putString("payload", "Hello from client");
            msg.setData(bundle);
            msg.replyTo = clientMessenger;
            serviceMessenger.send(msg);
        } catch (RemoteException e) {
            e.printStackTrace();
        }
    }

    @Override
    protected void onStart() {
        super.onStart();
        bindService(new Intent(this, RemoteService.class), connection, Context.BIND_AUTO_CREATE);
    }

    @Override
    protected void onStop() {
        super.onStop();
        unbindService(connection);
    }
}
```

**说明：**
`replyTo` 字段允许 Service 回传数据，无需额外 AIDL。若消息量大、需要并发处理，可让 Service 在子线程处理并通过 Handler 切回主线程更新 UI。
