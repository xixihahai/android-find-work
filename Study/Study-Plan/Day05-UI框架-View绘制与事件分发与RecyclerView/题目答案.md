## 口述题

#### 1. 画出 RecyclerView 四级缓存全景图，说明每级缓存的命中条件和复用成本（口述题）
**要点：**
- 一级 `mAttachedScrap`/`mChangedScrap`：仍在屏幕但待回收，命中成本最低。
- 二级 `ViewCacheExtension`（可选）：开发者自定义缓存。
- 三级 `mCachedViews`：默认大小 2，可复用同一 AdapterPosition。
- 四级 `RecycledViewPool`：跨 RecyclerView 共享，根据 viewType 维护队列。

**解析：**
滚动时优先从 Scrap（附着/变更）中取，确保动画状态保留；`ViewCacheExtension` 允许业务自定义子缓存；`mCachedViews` 存放滑出屏幕但仍在当前列表的 ViewHolder；`RecycledViewPool` 则在数据集差异大、切换 Tab 时提供跨列表复用。命中顺序直接影响滑动流畅度，可通过 `setViewCacheSize`、`RecyclerView.getRecycledViewPool().setMaxRecycledViews` 调整容量。

#### 2. 描述事件分发的完整链路：从 Activity.dispatchTouchEvent 到 View.onTouchEvent（口述题）
**要点：**
- Activity 收到事件后先交给 `Window.superDispatchTouchEvent`。
- DecorView -> ViewGroup 的 `dispatchTouchEvent`，内部先给 `onInterceptTouchEvent` 决定是否拦截，再下发子 View。
- 子 View 若消费事件（返回 true）则形成事件链，后续 MOVE/UP 由同一 View 处理。

**解析：**
流程：`Activity.dispatchTouchEvent` → `PhoneWindow.superDispatchTouchEvent` → `DecorView` → 根布局。ViewGroup 内部会遍历子 View，先调用 `dispatchTransformedTouchEvent`。若 `onInterceptTouchEvent` 返回 true，会终止向下传递改由自身 `onTouchEvent` 处理。事件被消费后，`ViewRootImpl` 会继续将后续事件发送到同一 View，直到 ACTION_UP/CANCEL。了解机制后即可利用自定义拦截、`requestDisallowInterceptTouchEvent` 处理嵌套滑动。

#### 3. requestLayout() 和 invalidate() 的区别，分别触发什么流程？（口述题）
**要点：**
- `requestLayout()` 会标记 View/父 View 需要重新测量布局，触发 measure/layout（甚至 draw）。
- `invalidate()` 只标记需要重绘，触发 draw（不会重新测量尺寸）。
- `postInvalidateOnAnimation()` 在下一帧刷新，更适合动画。

**解析：**
`requestLayout` 最终调用 ViewRootImpl 的 `scheduleTraversals()`，执行 measure→layout→draw，全局成本高，应避免在动画中频繁调用。`invalidate` 仅将区域加入 `Dirty` 列表，在下一帧重绘指定区域，适合更新内容但尺寸不变的场景。

## 场景分析题

#### 4. ViewPager2 + RecyclerView 嵌套，水平滑动和垂直滑动冲突怎么解决？说出方案和依据（场景分析题）
**要点：**
- 使用 `NestedScrollView`/`RecyclerView` 的嵌套滚动能力，通过 `requestDisallowInterceptTouchEvent` 控制父级拦截。
- 根据滑动角度判断：水平大于垂直则阻止父级拦截。
- 也可自定义 `LinearLayoutManager` 重写 `canScrollHorizontally/Vertically`。

**解析：**
ViewPager2 本质是 RecyclerView，默认会拦截水平滑动。可以在子列表的 `onInterceptTouchEvent` 中根据 `dx/dy` 动态调用 `parent.requestDisallowInterceptTouchEvent(true)`，或使用 `NestedScrollView` + `setNestedScrollingEnabled(true)` 让系统自动协调。若需要 finer control，可通过 `RecyclerView#setOnTouchListener` 判断角度。核心是确保同一方向只有一个控件处理事件。

#### 5. 一个列表有 10 种 viewType，滑动时频繁 create，如何优化？从缓存机制角度分析（场景分析题）
**要点：**
- 增加 `RecycledViewPool` 中每种 viewType 的缓存上限。
- 复用共享池：`recyclerView.setRecycledViewPool(pool)`，减少切换 Tab 时的 create。
- 尽量让 diff 运算减少全量刷新的次数。

**解析：**
默认每种 viewType 的上限为 5，可根据实际曝光量设置更大的值，如 `pool.setMaxRecycledViews(type, 20)`。另外要避免 `notifyDataSetChanged()` 导致缓存失效，可以使用 DiffUtil/`ListAdapter` 粒度刷新。此外，避免在 `onBindViewHolder` 创建临时对象，可缓存子 View，减轻 GC。

## 代码题

#### 6. 使用 ListAdapter + DiffUtil 实现一个支持 payload 局部更新的列表（代码题）
**要点：**
- 自定义 `DiffUtil.ItemCallback`，在 `getChangePayload` 中返回差异字段。
- 在 `onBindViewHolder(holder, position, payloads)` 中根据 payload 只更新变化的 View。
- 提供示例数据和提交列表方式。

**解析：**
`ListAdapter` 封装了 AsyncListDiffer，可自动计算 diff。通过 payload 可以避免整行重绘，提升性能。示例中定义 `UserItem`，对 `online` 状态做局部刷新。

**示例代码：**
```kotlin
data class UserItem(val id: Long, val name: String, val online: Boolean)

class UserAdapter : ListAdapter<UserItem, UserAdapter.UserVH>(DIFF) {

    companion object {
        private val DIFF = object : DiffUtil.ItemCallback<UserItem>() {
            override fun areItemsTheSame(oldItem: UserItem, newItem: UserItem) = oldItem.id == newItem.id

            override fun areContentsTheSame(oldItem: UserItem, newItem: UserItem) = oldItem == newItem

            override fun getChangePayload(oldItem: UserItem, newItem: UserItem): Any? {
                val payload = mutableMapOf<String, Any>()
                if (oldItem.online != newItem.online) payload["online"] = newItem.online
                if (payload.isEmpty()) return null
                return payload
            }
        }
    }

    override fun onCreateViewHolder(parent: ViewGroup, viewType: Int): UserVH {
        val view = LayoutInflater.from(parent.context).inflate(R.layout.item_user, parent, false)
        return UserVH(view)
    }

    override fun onBindViewHolder(holder: UserVH, position: Int) {
        holder.bind(getItem(position))
    }

    override fun onBindViewHolder(holder: UserVH, position: Int, payloads: MutableList<Any>) {
        if (payloads.isEmpty()) {
            onBindViewHolder(holder, position)
            return
        }
        val payload = payloads[0] as Map<String, Any>
        payload["online"]?.let { holder.updateOnline(it as Boolean) }
    }

    class UserVH(itemView: View) : RecyclerView.ViewHolder(itemView) {
        private val nameView = itemView.findViewById<TextView>(R.id.tvName)
        private val statusView = itemView.findViewById<View>(R.id.statusDot)

        fun bind(item: UserItem) {
            nameView.text = item.name
            updateOnline(item.online)
        }

        fun updateOnline(online: Boolean) {
            statusView.setBackgroundResource(if (online) R.drawable.dot_green else R.drawable.dot_gray)
        }
    }
}

fun demo(recyclerView: RecyclerView) {
    val adapter = UserAdapter()
    recyclerView.adapter = adapter
    adapter.submitList(listOf(UserItem(1, "Alice", true), UserItem(2, "Bob", false)))
    recyclerView.postDelayed({
        adapter.submitList(listOf(UserItem(1, "Alice", false), UserItem(2, "Bob", false)))
    }, 2000)
}
```

**说明：**
`getChangePayload` 只返回变化字段，`onBindViewHolder` 可根据 payload 局部刷新，避免重新绑定名称等静态信息。实战中可返回 data class 提升可读性。
